# 固定裂缝复测 MVP 设计（V0.5）

## 修订说明

本文修订自同名初版设计。初版基于 V0.3 代码写成，遗漏了测量层的硬编码约束，
并把"基线"和"上一次记录"当作同一个概念。本版在 V0.4（AI 现场复核）代码基础上重写，
修正上述问题，并把现场全景的归属显式化。

被本版取代的初版结论：

- 初版让操作者手填左右各四个标靶 ID；本版改为系统自动分配。
- 初版只输出一个毫米变化；本版输出"较基线累计"与"较上次"两个。
- 初版未涉及 `backend/app/cv/pipeline.py`；本版将其列为首个任务。
- 初版把多场景受控精度验证列入范围；本版移出，推迟到 V0.6。

## 目标

把 GeoRecheck 从"一个预置点位的演示"升级为"任何人能给任意一条真实墙缝建立视觉复测点、
打印标靶、并长期跟踪相对变形"的本机 MVP。

V0.4 已交付的几何测量、质量门控、AI 现场复核与人工逐条确认机制全部保留，不做替换。

## MVP 定义：验收剧本

能完整演完下面九步，即视为交付。

1. 打印 ChArUco 标定板，拍 15–25 张，在标定页跑一次；相机 profile 从 `is_demo_profile` 变为已标定。
2. 在「裂缝管理」新建点位 `MP-W02`，填写隐患点、构筑物、裂缝编号、位置描述，可选上传现场全景；
   系统自动分配八个空闲 AprilTag ID。
3. 在点详情页下载复测贴 PDF，得到两页 A4，页眉印有点位编号与实际标靶 ID。
4. 以 100% 比例打印，用尺核对 100 mm 边，贴到硬质衬底，再贴在墙缝两侧同一平面上。
5. 详情页「采集基线」，拍照，通过质量门控，人工确认；点位状态变为已建档。
6. 隔日回到详情页「开始复测」，拍照，得到「较基线累计 +X mm」与「较上次 +Y mm」。
7. 对该次复测发起 AI 现场复核；系统自动取用点位全景与上次已确认近景，操作者逐条接受、
   拒绝或编辑观察项。
8. 确认后生成可打印记录，并在详情页看到按时间倒序的记录序列。
9. 「一分钟演示」与五个 Demo Case 全部不受影响，仍可正常演示。

## 关键设计决策

### 1. 测量层按点位参数化

`backend/app/cv/pipeline.py` 的 `measure_image()` 在第 59、60、87、88 行写死 `DEMO_LEFT` 与
`DEMO_RIGHT`，即只测量标靶 301–308。检测器能识别其他 ID，点位也能匹配，但位姿解算对两块板
都返回 `None`，质量门控随即拒绝。因此在修正此处之前，任何新建点位都无法产出测量结果。

`estimate_board_pose()`、`rectify_board()` 与 `measure_planar_relative()` 本身已接受
`BoardSpec` 参数，只是默认值指向演示板。因此改动限于 `measure_image()` 增加两个带默认值的
关键字参数，现有八处调用点无需修改。

点位身份来自图像中的标靶，而选择标靶规格又需先知道点位。为此把检测拆出独立函数
`scan_marker_ids()`：先扫描得到 ID，匹配点位，取得该点位的标靶规格，再执行完整测量。
检测因此运行两次，代价约 50–100 ms。选择该方案而非传入解析回调，是为了让 `pipeline.py`
保持纯视觉计算，不引入数据库依赖。

同时删除 `board_geometry.py` 的 `board_for_marker()`。该函数全仓库无调用者，且把
"只存在两块演示板"的假设埋在几何层。

### 2. 标靶身份：新增 `MarkerAssignment` 表

标靶 ID 全局唯一是一条安全属性而非校验规则：两个点位共用一个标靶，后果是测量结果被记入
错误的裂缝。因此以主键约束表达，而不是以函数校验表达。

```python
class MarkerAssignment(Base):
    __tablename__ = "marker_assignments"
    marker_id: Mapped[int] = mapped_column(Integer, primary_key=True)
    monitor_point_id: Mapped[str] = mapped_column(String(64), index=True)
    side: Mapped[str] = mapped_column(String(8))      # left | right
    slot: Mapped[int] = mapped_column(Integer)        # 0..3
```

`slot` 不可省略。`BoardSpec.marker_corners_mm()` 以 `marker_ids.index(marker_id)` 推算该标靶
在板上的行列位置，元组顺序直接决定物理坐标。逗号分隔字符串是偶然保住顺序，`slot` 是明确保住。

该表同时使标靶分配与反查各自成为一次查询：分配读取已占用 ID 集合，反查用
`WHERE marker_id IN (...)` 替代现有的逐点位扫描。

`MarkerAssignment` 是唯一事实来源。`MonitorPoint.left_marker_group` 与 `right_marker_group`
因非空约束保留，在建点时由分配结果派生写入一次，此后只写不读，在模型中标注为遗留字段。
`point_to_dict()` 改为从分配表读取，对外 JSON 形状保持不变。

迁移时把既有点位的两个字符串列回填为分配记录，操作幂等。演示点位 MP-03 因此占用 301–308。

### 3. 标靶 ID 自动分配

AprilTag 36h11 字典共 587 个 ID，每点位占八个，因此最多支持 73 个点位。分配取**最低的一段
连续八个空闲 ID**：连续便于打印页标注与人工核对，取最低则可回收点位删除后留下的空洞。
左板取前四个，右板取后四个，`slot` 为块内下标。

分配、建点与八条分配记录写在同一事务内。单机场景下并发属理论问题，但主键约束使其免费成立。

操作者不需要看见也不需要输入这些数字。

### 4. 基线与双数字

点位状态由数据推导，不额外存字段：`baseline_inspection_id` 为空即未建档。

```
未建档 --采集基线--> pending 基线 --确认--> 已建档
已建档 --开始复测--> pending 复测 --确认--> 已确认记录
```

未建档时发起普通复测返回 422。已建档后再次发起基线采集返回 422；标靶重贴后的重新建档属于
V0.6 范围。

四个毫米量的定义：

```
opening_delta_mm          = 本次 planar_x - 上次已确认 planar_x     # 较上次
shear_delta_mm            = 本次 planar_y - 上次已确认 planar_y
opening_since_baseline_mm = 本次 planar_x - 基线 planar_x           # 较基线累计
shear_since_baseline_mm   = 本次 planar_y - 基线 planar_y
```

基线采集自身四个值均为 0.0。首次复测时上次即基线，两组数值相等，界面照常并列显示。

`opening_delta_mm` 与 `shear_delta_mm` 保持 V0.4 既有含义不变，因此历史记录与既有测试的语义
不受影响。

**异常门只作用于单期变化。** 现有 `abs(opening_delta) > 50.0` 判定为拒绝的规则是为单期突变
设计的。累计值在长期监测下会合法超过该阈值，若套用同一规则，一条被持续跟踪的裂缝会在某天
开始被系统拒绝，且表现为质量问题。累计值不设上限。

**测量值提升为真列。** `planar_position_mm` 目前存放在 `quality_reasons` 的 JSON 内。基线是被
长期引用的数据，以字符串键取值过于脆弱，因此提升为 `planar_x_mm` 与 `planar_y_mm`。同时把
`services/inspection.py` 中装载上次记录却命名为 `baseline_planar` 的变量改名为 `previous_planar`。

**堵住静默回退。** V0.4 在标靶匹配失败且携带有效 `demo_case_id` 时会回落到 MP-03。引入多点位后
该路径的风险是"标靶未拍清"变为"记入他人名下"。规则：请求携带显式 `point` 参数时永不回退；
图像识别出的点位与该参数不一致时返回 422 并指明实际点位；无法识别点位时返回 422，不作推测。

### 5. 相机标定：软提示

`data/camera_profiles/default_camera.json` 是 `is_demo_profile: true` 的演示配置，焦距写死为
1500.0、畸变系数全为零。以它计算真实照片，毫米结果不可信。

MVP 不以标定作为硬门槛：未标定仍可完成全流程，但结果页、记录页、历史与导出全部标注
"未标定相机，毫米值仅供参考"，并将该标记持久化到 `Inspection.camera_profile_is_demo`，
使记录在事后仍可分辨。

### 6. 现场全景归属点位

现场全景是点位属性，不是单次观测量。

依据一：在 `prompts/field_review_system.txt` 中，变化比较只发生在图2与图3之间（判定顺序第 1 条），
图1 仅在第 24 条出现，作用是提示模型不要把场地固有特征当作新增变化。它是背景常量。

依据二：V0.4 界面已经如此运作。`CapturePage.tsx` 的三图面板中，全景与上次近景来自案例资源，
只有本次近景具备上传入口，按钮文案即为"上传本次近景"。

依据三：五个 Demo Case 各自对应一张不同的场景图，一个案例即一个隐患点。"每点位一张全景"
已经成立，只是编码在目录结构而非数据模型中。

依据四：拍摄全景通常需退开十余米，与走近拍摄近景是两个动作。要求每日巡查三次的人员每次
重复两遍不具可行性。

**风险与缓解。** 现场全景会随汛期植被、堆放物与排水状态变化而过期。AI 用它判断哪些是固定
特征，过期全景会把新出现的堆物或水迹误判为固有特征，导致漏报；在本场景中漏报比误报更严重。
因此点位级全景必须同时具备：

- 点位详情页提供「更新现场全景」入口，不是一次性锁定；
- 每条 `Inspection` 记录本次复核所用的全景版本与拍摄时间；
- 全景拍摄时间距今超过 90 天时，结果页与详情页提示建议更新。阈值取一个汛期周期，
  定义为 `CONTEXT_PHOTO_STALE_DAYS = 90`，可经环境变量覆盖。提示不阻断任何操作。

三条缓解措施属于 MVP 范围，不推迟。

### 7. AI 现场复核泛化

`services/ai_review.py` 的 `_case_paths()` 只能读取 `data/demo_cases/{case_id}/` 下的三张固定
图片，因此新建点位无法使用 AI 复核。将其替换为通用取图器：

```python
@dataclass(frozen=True)
class ReviewImages:
    context: Path      # 图1 现场全景
    previous: Path     # 图2 上次近景
    current: Path      # 图3 本次近景
```

- Demo Case 分支维持现状，读取案例目录。
- 真实点位分支：`current` 取本次证据目录下的 `original.png`，`previous` 取上一次已确认记录的
  同名文件，`context` 取点位的现场全景。

两条硬约束：

- **基线采集不提供 AI 复核。** 不存在"上次近景"，图2 缺失会使 prompt 的整套保守判定失效。
- **不把累计值传给模型。** `run_field_review()` 的元数据目前只含 `opening_delta_mm`，而 prompt
  第 22 条正在专门对抗数值锚定。再增加一个数值只会加大风险。模型的数值输入维持单一。

配套调整：`build_confirmed_record_text()` 现固定叙述"较上期张开"，改为同时叙述累计与单期；
`run_and_persist_ai_review()` 中的 `inspection.demo_case_id` 对真实点位保持为空。

`AIReview` 与 `AIReviewItem` 两张表及人工逐条处置机制完全复用，不作修改。

### 迁移

`migrate_schema()` 目前仅执行 `ALTER TABLE ADD COLUMN`。上述新增列沿用该方式。

`monitor_points` 的经纬度改为可空需要 SQLite 建新表、拷贝、改名。该表实际最多 73 行，
迁移前以"检测到旧的非空约束"为守卫，只执行一次，不删除任何数据。

选择表重建而非"写入 0.0 加布尔标志"，是因为默认演示定位模式会把点位坐标抄入检查记录，
写入 0.0 等于在台账中留下一条位于几内亚湾的记录。

不引入新依赖。

## 用户路径

### 裂缝管理

操作者新建监测点，填写隐患点、构筑物、裂缝编号与位置描述，可选上传现场全景。系统自动分配
标靶并给出可打印 PDF。打印贴装完成后采集基线并人工确认，该点位进入可复测状态。

### 裂缝详情与复测

操作者从列表进入详情，查看基线、最近一次已确认记录与历史变化，点击开始复测后上传照片。
系统以标靶自动识别点位，执行既有质量门控与相对位移计算，输出累计与单期两个变化量。
可选发起 AI 现场复核并逐条处置。操作者确认后生成记录。

## 边界与非范围

本 MVP 不提供地质灾害风险判断、预警、撤离建议或安全结论。所有测量结果必须由受过培训的
人员复核，不替代人工现场巡查、专业裂缝监测设备或既有地灾业务系统。

明确不做：风险等级、绝对裂缝宽度结论、账户与多人协同、云端同步、地图平台、原生移动应用、
裂缝分割推理接入主链路、多场景受控精度基准（推迟至 V0.6）。

## 受控验证的表述边界

本次迭代交付的是链路可用性，不是现场精度。

既有的 MAE 0.496 mm、P95 1.002 mm 仅在受控合成场景上成立。实拍链路走通后，可以陈述的结论
仍然只是"该流程可以完整执行"，不能推导出实拍精度。该限制同时写入 `docs/VALIDATION.md`。

打印缩放误差会按比例直接转化为测量误差：打印机缩放至 98% 会使所有毫米值系统性偏差 2%。
复测贴 PDF 上的 100 mm 校核边是唯一防线，必须实际测量。复测贴须贴附于硬质衬底，左右两块
须位于同一平面，否则平面假设不成立。

## 验收条件

1. macOS 与 Windows 使用同一套开发启动脚本；E2E 自动选择正确的 Python 可执行文件。
2. 可创建一个非预置点位，系统自动分配八个唯一标靶 ID，并下载到印有该点位编号与实际 ID 的
   两页 PDF。
3. 以该点位标靶合成或拍摄的图片可完成位姿解算并产出测量结果，证明测量层不再受演示标靶限制。
4. 未完成基线建档时，普通复测被拒绝并提示先行建档。
5. 基线确认后，复测同时输出较基线累计与较上次两个变化量；单期异常门生效，累计值不受其限制。
6. 携带显式点位参数的请求，在图像识别结果不一致时被拒绝，且不回落到演示点位。
7. 管理界面可查看多个点位、详情、建档状态、最近确认变化与历史记录。
8. 真实点位可发起 AI 现场复核，取图来自点位全景与上次已确认证据；基线采集不提供该入口。
9. 未标定相机时，结果页、记录页与历史均带有标注，且该标记在记录中持久保存。
10. 现场全景可在建点后更新；每条记录留存本次所用的全景版本；全景超过 90 天时界面给出
