# GeoReCheck V0.5 Showcase Mode

## 目标

V0.5 不推翻 V0.4，而是在既有 React/FastAPI、AprilTag/透视校正、质量门控、StepFun 可见变化复核、SQLite 持久化和人工确认之上增加一个比赛展示层。它把一线监测员的完整动作讲清楚，而不是只展示一个算法结果页。

入口：`http://127.0.0.1:5173/showcase`

## 三栏大屏

1. **左侧现场**：用公开建筑上下文素材构成 2.5D 巡查现场，展示巡查员沿路径到达复测点、拍全景、换机位拍近景；这不是贵州真实事故影像。
2. **中间手机**：逐步呈现任务、到达、全景、近景、处理、结果、人工确认和记录界面。
3. **右侧解释**：说明当前动作、岗位价值和职责边界，持续强调几何负责毫米变化、AI 负责可见现象、人工负责采纳、系统负责留痕。

## Golden Path（约 50–60 秒）

| 步骤 | 屏幕故事 | 主要输出 |
|---|---|---|
| 01 接到任务 | 确认 MP-03 / CRACK-W01 | 点位与检查对象 |
| 02 到达现场 | 沿路径到房屋前 | 现场上下文 |
| 03 拍摄全景 | 房屋、挡墙和排水区域入镜 | AI 上下文图 |
| 04 拍摄近景 | 从不同机位拍裂缝与复测贴 | 本次几何输入 |
| 05 自动处理 | OpenCV 几何与可见变化复核 | 两条独立职责链 |
| 06 查看结果 | 先显示毫米变化，再显示 AI 提示 | `+4.8 mm` 与疑似水迹 |
| 07 人工确认 | 监测员确认或不采纳 | 人工决定 |
| 08 自动留痕 | 图像、数值和结论进入记录 | 可审计记录编号 |

页面支持自动演示、暂停、上一步、下一步和重新开始。自动演示进入实时模式的人工确认步骤时会停下，避免替监测员作决定。

## 三个展示故事

- `case_03_seepage`（默认）：裂缝张开约 `+4.8 mm`，可见变化提示为疑似新增水迹；
- `case_04_spalling`：较小的裂缝变化，提示疑似局部剥落；
- `case_05_quality_fail`：近景模糊，质量门控拒绝输出毫米值，记录失败原因并要求重拍。

每个案例的 `previous_close.jpg` 与 `current_close.jpg` 是不同拍摄角度，不是同一图片重复摆放。角度变化通过复测贴定位和正视透视校正处理；当前受控验证仅说明 Demo 数据可重复，不代表野外精度。

## 展示模式与实时模式

### 展示模式（默认）

- 读取仓库中的本地图片和已验证样例结果；
- 不调用 StepFun 或其他外部网络；
- 适合网络不稳定的比赛现场；
- 页面明确标记“本地已验证样例”，不会伪装成实时推理。

### 实时模式（可选）

- 真实调用本机 FastAPI `/api/measure`；
- 质量通过且 StepFun 已配置时，真实调用三图 AI 复核；
- StepFun 超时、额度或网络失败不会覆盖或阻塞几何结果；
- 人工确认后继续调用既有持久化接口生成正式记录。

## CMD 启动

直接双击项目根目录的 `一键启动前后端.cmd`。它使用指定 Python：

```bat
D:\Anaconda\_envs\PulseWeave\Scripts\python.exe
```

脚本启动 FastAPI 和 Vite，等待健康检查通过，然后用 Google Chrome 打开 Showcase。命令窗口必须保持打开，按 `Ctrl+C` 停止前后端。

## 能力边界与待验证事项

- 不判断地灾风险、不自动预警、不输出撤离或安全建议；
- 不替代基层监测员或专业监测设备；
- 现场图、位移、水迹、剥落和模糊均属于开放素材基础上的受控演示，不是真实贵州监测数据；
- 实体复测贴尺寸、真实相机标定、室外光照与长期贴装仍需物理实验；
- 当前 2.5D 现场用于讲故事，不是 GIS、数字孪生或真实人员定位。
